# 更新 Craftime 规范索引

先读取 [跨 Agent 执行方式](../craftime-figma-ui/references/host-compatibility.md)。无面板/附件协议时，按其中的纯技能方式执行；下文仅适用于 Codex 的面板、附加状态与后续操作语法不在其他宿主强制执行。

先读取并遵循 [规范使用反馈](../craftime-figma-ui/references/interaction.md)，显示“更新规范”启用提示。结束时报告读取覆盖范围与索引保存状态；设计引用和画板检查标为不适用。

先读 [基础规则](../craftime-figma-ui/SKILL.md) 和 [上次索引](../craftime-figma-ui/references/design-system.json)。

1. 先按索引 authorityRouting 区分基础定义、业务资产与固定区域。基础规范从组件库 `03EUC7nSmTdbnEjMOWAQ3U` 读取；旧 coverage 只描述 2026-10-11 的业务来源，不能当成组件库缺口。用已连接 Figma 工具读取本次规范源的页面清单、文字/颜色/效果样式、变量与变量集合。用户授权盘点组件时，可逐页只读查询组件定义；按该环境 Figma 技能的页面上下文规则组织调用。规范刷新不包含查找现有业务 UI 页面，不自动读取业务画板截图；只有用户明确要求查找现有 UI 时才进行该工作。
2. 将当前定义与索引比较，报告样式新增/删除/重命名/参数变化、变量变化、组件来源变化及覆盖缺口。记录读取日期、源 file key、资产 ID/key 和适用范围。
3. 组件名不证明平台或用途；现存组件仍记为候选。没有本地变量不代表没有视觉规则。不能从业务稿抽样拼出未经确认的全局颜色/圆角表。
4. 仅在所有相关读取成功时，将全量盘点标为完成。部分读取必须记录未覆盖页面及失败项，保留未读取资产的旧记录及旧日期，不能当作删除。
5. 用户只要求核对时输出差异即可。用户要求刷新本地维护源时更新获准编辑的源索引；安装缓存不作为维护源，不修改 `~/.codex/plugins/cache`。
6. 若缓存目录只读或没有维护源，给可复核的更新数据/差异并说明保存位置。做页面依然直接读实时规范，不必等待索引发布。
7. 只有用户要求发布工作流程/索引更新时才更新插件发布版本，沿用已验证的插件 ID 和现有管理方式。账号托管插件通过 Plugin Creator 的更新指引；Git 托管插件通过仓库发布，不能随意另建同名插件。

此流程不修改 Figma 规范源，不设置定时监控，不自动分享或发布插件。
