# 规范使用反馈

本协议用于执行后的证据反馈。发送前的开启状态由 [输入框规范开关](composer.md) 的真实宿主附件提供；聊天反馈不代替该附件。安装或可发现技能不代表已经执行。

## 何时显示

- 输入框已有已开启的 Craftime 附件时，直接执行相关流程。开始只简短说明本次读取的规范范围，不再重复发送“已启用”卡片；读取结果和交付证据仍需报告。
- 没有输入框附件、但用户明确要求执行本插件时，加载流程后可使用下方聊天启用提示，同时说明它是本次执行提示，不是发送前开关。
- 仅有官方 Figma 工具、只看了插件名称或只发现安装缓存时，不能显示“Craftime 规范已启用”。
- 版本从当前执行来源的 [plugin.json](../../../plugin.json) 读取。不得用“最新版本已保存”推断安装端已加载该版本。通过项目维护源执行时注明“执行来源：项目维护源”；安装版未核实时不虚构其版本。
- 用户明确要求本次跳过规范时尊重该要求，显示“Craftime 规范：本次未启用（用户要求）”。不能继续声称已按规范交付。普通、不相关任务不增加这些提示。

## 开始提示

按当前事实填入以下格式。标题及状态文字保持一致，其余行简短：

> **🟢 Craftime 规范已启用 · v{实际执行版本}**
> 操作：{按规范设计 / 检查设计 / 更新规范 / 接入检查}
> 规范源：[Craftime UI](https://www.figma.com/design/h2Yu0Mg9J23KCatfp4uBgh/Craftime-UI)
> 本次读取：{尚未读取 / 正在读取 / 已读取，列出实际范围}
> 目标：{本次目标文件或画板链接；没有目标时写“尚未指定”}

若是接入检查，加上“这只证明接入情况，不代表已有设计通过检查”。仅询问状态时采用状态技能的查询格式，不为了查询而假装启动一个设计任务。

## 证据阶段

四个阶段分开判断，不把一个阶段的成功当成下一个阶段通过：

| 阶段 | 显示状态 | 所需证据 |
| --- | --- | --- |
| 插件流程 | 已启用 / 本次未启用 / 无执行记录 | 本次实际加载了相应技能并采用其流程；查询过去任务时需过去的执行证据 |
| 实时规范 | 已读取 / 部分读取 / 未读取 / 读取失败 | 本次规范源读取结果，列明平台、语言、页面或资产范围；缓存不能算本次实时读取 |
| 资产引用 | 已验证 / 部分验证 / 未验证 / 不适用 | 目标节点的 Text Style、变量绑定及组件关联；只看相同外观或数值不算引用 |
| 交付检查 | 通过 / 有偏差 / 有例外 / 待验证 / 不适用 | 对应实际属性和截图的检查结果；所有适用范围均有证据时才可用“通过” |

权限问题或规范自身冲突要明确展示。未知属性、未适用规则与确认违反规则的偏差分开。不得制造完整性百分比、得分或没有读取证据的通过计数。

## 结束提示

设计或审稿结束时，在结果中显示：

**Craftime 规范检查 · {通过 / 有偏差 / 有例外 / 待验证}**

| 检查项 | 本次结果 |
| --- | --- |
| 插件流程 | {实际启用状态、执行来源、版本} |
| 实时规范 | {状态；读取范围及时间} |
| 样式与组件引用 | {状态；核实的绑定及来源，或未验证原因} |
| 画板检查 | {状态；属性与截图范围} |
| 待处理 | {偏差、例外、冲突或未完成项；无时明确写“无”} |

- 附本次画板链接；每个确认问题附节点证据。状态表不能代替详细证据。
- 有失败或阻塞时也显示结束提示，不能省略反馈。只核实接入或更新索引时，标题分别使用“Craftime 接入检查 · …”或“Craftime 规范索引 · …”；资产引用与画板检查标为不适用，不冒充设计完成。
- 未检查的颜色、间距、圆角、交互等不能暗示已经通过。

## 可点击的后续操作

在 Codex 结束结果中使用下面的原生后续操作语法；它们是用户点击后才发送的请求，不自动执行、不自动修复。保持动作对应当前实际目标。其他不支持该语法的客户端只显示同义的简短文字用法。

- :codex-followup[查看本次规范使用情况]{prompt="使用 Craftime Design 的 $craftime-status，根据当前聊天的执行证据，报告刚完成的任务是否启用了插件、读取了哪些规范、引用和检查是否有证据。"}
- :codex-followup[重新检查设计]{prompt="使用 Craftime Design 的 $craftime-review，只读检查本聊天最后交付的 Figma 画板，显示规范启用状态及检查结果；目标不明确时先澄清。"}

接入检查结束时，提供以下两个入口即可：

- :codex-followup[按规范做页面]{prompt="使用 Craftime Design 的 $craftime-figma-ui 开始页面设计，先显示规范启用状态，并根据已有上下文确定需求；缺少目标 Figma 文件、平台、语言或业务需求时只询问必要信息。"}
- :codex-followup[检查已有设计]{prompt="使用 Craftime Design 的 $craftime-review 检查已有 Figma 画板，先显示规范启用状态；已有目标就直接检查，缺少目标时询问画板链接。"}

## 当前插件的边界

执行反馈来自 agent 的检查证据；输入框开启状态来自自己的 MCP App。它们都不是全局强制拦截。不要声称每个团队项目都会因为安装而自动加载；也不要把开启附件当成画板通过检查。没有执行证据时明确写“未能确认使用”。
