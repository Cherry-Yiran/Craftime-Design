# 跨 Agent 执行方式

同一套 Craftime 设计、评审、接入、状态与索引规则可通过 Agent Skills 使用。本说明处理宿主差异，不改变基础规范、授权范围或已确认的设计决策。遇到下文附件/面板专属步骤时，先按本说明选择适用方式。

## 采用规则与当前聊天状态

- **支持 Craftime 面板和模型上下文附件的宿主**：沿用 [输入框规范开关](composer.md)。只在有真实宿主确认时报告已附加；明确关闭或移除的状态优先于历史开启记录。插件安装不代表当前聊天已开启。
- **没有该面板或附件协议的宿主**（如普通 Claude Code、Cursor、Gemini CLI、Copilot、OpenCode 环境）：用户明确请求 Craftime，或已获授权的项目/技能路由实际采用本流程时，直接读取相关技能执行。简短说明“本次采用 Craftime 规则”；不要求用户先打开 Codex 面板、不输出 `:codex-followup`，不伪造 `craftime.enabled`、updateId、绿色附件或全局开启状态。用户本次要求跳过或关闭时停止自动采用。
- 不支持附件不等于缺少规则或拒绝工作。将“本次已采用规则”“实时规范已读取”“资产引用已验证”“交付检查通过”分别依据实际证据报告。未来聊天是否自动采用取决于宿主实际配置，不能承诺所有 Agent 永久开启。

## Figma 与检查能力

- 本包 MCP 提供 `craftime_get_rules`、`craftime_check_design` 与可选的 `craftime_open`。前两者可供普通 stdio MCP 客户端调用；后者只有宿主支持 MCP App 及所需附件扩展时才具有面板作用，不支持时跳过。
- 这些工具不会读取或编辑 Figma。每位成员需在自己的 Agent 中配置实际可用的 Figma 工具、认证及文件权限；Codex 的 `.app.json` 依赖不会自动迁移到其他宿主。只读 Figma 工具不能用来承诺原生写回。
- 使用本机实际可用的 Figma 工具与该工具官方指引。不假定每个环境都有 `use_figma`、`figma-use` 或创建组件技能；这些名称的前置加载只适用于确有该能力的环境。能力缺失时说明“规范阅读 / 本地 Demo / Figma 只读 / 原生可编辑写回”中实际能完成的部分，继续独立工作，不冒充完成写入。
- 没配置本包 MCP 时可直接读技能文件，并用随技能附带的检查脚本核对真实记录。没有 shell 能力则按规则人工核对并说明限制。读取本地规则不算实时读取 Figma，合成测试记录不算真实画板验收。
- 不支持原生后续操作按钮时提供同义的短文字用法，不创建未知指令或自动执行下一项任务。

## 来源与版本

技能的相对链接按当前 `SKILL.md` 或参考文件所在目录解析。安装时应保留五个技能目录、引用与脚本的完整关系，不只复制入口 Markdown。

纯技能安装使用本目录 [runtime.json](runtime.json) 的打包版本；完整插件可另核对根清单。打包版本证明文件来源，不证明宿主已加载、当前任务已执行或实时规范未变化。安装与能力矩阵见仓库 `docs/COMPATIBILITY.md`；该仓库文件不随纯技能安装时，无需阻塞任务。
