## 必须完成的检查

1. 在授权目标子树中识别实际可见的分隔线，包括 LINE、细长 RECTANGLE 或 FRAME；不只按 Divider 层名找。按钮外框、表格有意义的强边界、图片遮罩和导航既有分隔不能自动套用普通内容分隔规则。
2. 用只读 Figma 调用返回每个待查节点的 `id`、`role`、当前渲染 `hex`、节点 `nodeOpacity`、Paint `paintOpacity`、视觉 `thickness` 和 `variableNames`（实际绑定及解析别名链中的名称）。同时核对所在祖先是否隐藏、有透明度或叠加效果；祖先效果要额外报告，脚本不能证明最终合成颜色。
3. 读取 [机器规则](color-semantics.json)，执行 `node scripts/check-color-semantics.mjs /absolute/path/to/readback.json`，路径相对本技能目录。也可在可用的 JavaScript 环境执行同等检查，保留结果。缺少必要值、绑定或覆盖证据时应为“待验证”。
4. 将每个问题连到真实节点并给实际用途、实际值、规范值和来源。已有组件明确特例或用户例外不改源母版，单列来源与理由；不要为通过检查而把错误分隔线改称“装饰描边”。
5. 在授权范围内修正错误，再读回属性并检查实际截图。普通页面任务不授权修改共享变量、固定顶部/导航或其他历史画板。

构造代码分别选择 `separator`、`decorativeBorder` 和 `controlBorder`。不要用统一的 `border` 配色函数给所有细线赋色，也不要降低描边色透明度模拟分隔色。脚本通过只说明输入记录通过该项检查；必须保留覆盖范围、来源和截图证据，不能由此宣布整页或交互验收通过。
