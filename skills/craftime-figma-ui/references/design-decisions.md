# 设计决策与交付范围

2026-11-02 用户从近期设计反馈中明确选定以下四项更新插件。它们约束设计与交付过程，不新增全局尺寸、颜色、业务状态或审批流程。用户本次明确要求与最新定稿优先。

## 移动端独立设计

- 制作、修改或检查 App / H5 / Mobile 前，先读取正式移动端布局与间距定义，再读取同模块现有移动端页面的最新节点和截图。针对触屏、窄屏阅读和操作位置独立组织信息，不将 Web 直接缩窄或照搬 Web 间距。可共用业务语义与已确认基础变量。
- 优先用用户指定或项目已记录的来源。2026-10-27 用户确认的限定例外允许查找对应模块的移动端参考；不扩展到无关业务或 Web。来源缺失或不可读时说明缺口，继续不依赖它的工作，不虚构已读取。
- 核对页面边距、行高、列表行与图文间距、标题与辅助信息的关系、尾部控件位置、点击热区及系统安全区。聊天气泡、成员列表和弹窗分别参考对应场景，不把一个原稿实测值升级为全局规范。
- 使用 Auto Layout 和已确认变量；按任务目标视口检查真实尺寸截图与所在区域。局部控件或图标修改只复核相关上下文，不额外制作完整页面。属性写入成功不等于移动端布局通过。

## 简洁与信息密度

- 保留识别、理解和操作所需的信息，优先通过对齐、间距与分组形成层次；减少无用途的分隔线、重复标题、重复统计及解释性文案。简洁不等于全用文字或一律不用分隔线；图标、作品缩略图和克制的表面区分可帮助扫描。
- 卡片大小、单屏可见数量、列数及滚动区域按模块内容和用户要求判断，不机械照抄参考图比例，也不通过缩小规范字号、压低行高或热区来塞入更多内容。不自动增加装饰、标签、厚重阴影或强调色。
- 不以“简洁”为由删除用户提供的文案、数据、功能或必要条款。折叠、省略与隐藏按已确认需求执行；涉及未授权的信息删减时先作为建议。局部的标签两行、简介五行、按钮尺寸、卡片灰底或列数都不是全局标准。
- 在现有截图检查中确认信息主次、阅读顺序、留白与控件轻重；发现具体问题才修正并复核受影响部分，不新增审美评分、固定复审轮次或例行用户确认。

## 图标语义避撞

- 继续遵守 [图标规则](icons.md)：MingCute 来源、真实可编辑 Stroke、最终尺寸下 1.67px 及变量绑定。来源与描边合规不能替代语义判断。
- 选图标前明确它表示的对象或动作，并与当前页面及已提供的同模块关联图标比较。例如“想做”应与“点赞”“收藏”在含义和轮廓上可区分；只换颜色或添加小加号不自动证明已消除混淆。
- 使用当前稿、用户提供参考和已读组件做比较，不因语义检查自动浏览无关业务 UI。缺少对照来源时标记待验证，不凭记忆宣称全产品无冲突。
- 在最终使用尺寸和实际控件上下文中核对辨识度。用户要求先看方案或生图时，先交对应方案，不提前替换正式图标；局部选型不授权改其他图标或共享母版。

## 交付范围与定稿同步

- 根据已有上下文确定目标文件/节点、平台、语言、交付媒介与规模：效果图、局部组件、一屏、完整流程或全部状态。可推断时直接执行，不额外设审批；受保护区域继续保留。
- “看一页样式”只用足以展示一屏的代表数据，不把完整 Demo 数据集全部导入 Figma。屏幕尺寸、卡片数量以本次目标为准，不把一次交付的尺寸或数量写成通用规范；用户明确要完整流程或全部状态时则交全。
- 用户中途缩小范围时停止不再需要的批量生成、导入与同步，清理本次产生且不再需要的临时交付内容，保留用户原有资产。无法取消的后台任务应说明真实状态并隔离其结果，不宣称取消成功或继续混入交付稿。
- 延续页面或同步定稿前，重新读取用户最新修改后的目标节点、可见文案和截图。旧层名、旧快照和助手建议不能覆盖现稿；不补回用户删除的状态或擅增业务规则。
- 用户明确要求同步全部状态时，列出实际目标节点、平台与状态范围，区分共用样式和状态内容，保留数据差异、禁用/错误/加载表现、实例关联和既有交互。按实际存在及授权范围同步，不为凑齐类别新增状态。
- 完成后逐项读回目标清单，截图检查整体上下文及有差异的代表状态，列出遗漏、失败与尚未验证的交互；改完一个示例或一个母版不等于所有目标完成。删除旧稿仅在明确授权后执行，并先核对引用与入链。

## 使用现有交付记录

按任务相关性，在现有交付记录中说明移动端来源与视口、信息密度的具体改动、图标的语义对照，以及目标清单、最终来源、已完成/未完成项和临时任务状态；无需为每次任务额外建报告。

[读回检查](readback-checks.md) 仅验证提交记录。结构化工具不自动读取 Figma、识别截图语义或证明所有状态同步与整页验收通过。缺少实际证据时标记待验证。
