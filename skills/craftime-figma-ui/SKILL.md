# 按 Craftime 规范设计

当前聊天的 Craftime 规范附件已开启时，页面需求默认采用以下流程，不要求用户在每条指令中指定插件。遵循 [输入框规范开关](references/composer.md) 和 [规范使用反馈](references/interaction.md)。附件已关闭时不因历史开启记录自动采用；用户本次明确要求采用时优先。结束时显示实际规范检查结果。

规范源：[Craftime UI](https://www.figma.com/design/h2Yu0Mg9J23KCatfp4uBgh/Craftime-UI)，file key：`h2Yu0Mg9J23KCatfp4uBgh`。

[资产索引](references/design-system.json) 是有日期的查找辅助，不是实时规范。字体、颜色、间距、圆角及组件属性以本次读取的 Figma 定义为准，不能仅凭缓存声明“使用最新规范”。值的变化无需先发布插件。

## 开工

- 从任务确定平台（Web / App / H5）、语言、目标文件/画板和业务目标。能推断的直接执行；只澄清影响设计依据的歧义。
- 读取规范中相关文字样式、变量、组件和同端业务页。只检查本次有关部分，不把封面读取结果当成完整文件。
- 先说明本页使用的规范来源与适用组件。区分明确基础规范、业务组件既有定义与本次方案选择。
- 通过已连接的 Figma 工具操作。调用 `use_figma` 前加载该环境的 `figma-use` 指引；构建整页加载 `figma-generate-design`；创建组件加载 `figma-generate-library`。对应技能不可用时使用环境提供的官方工具指引，不依赖维护者电脑上的绝对路径。

用户的明确要求优先于插件约定；记录例外。旧走查、探索效果图和社区 UI Kit 不自动成为 Craftime 标准。

## 基础规范

### 文字

已确认的文字角色来自 `Group/Craftime/Web/EN/`：

| 用途 | 样式后缀 |
| --- | --- |
| 页面标题 | Heading/Page |
| 区块标题 | Heading/Section |
| 正文 | Body/Default |
| 紧凑正文 | Body/Compact |
| 注释 | Body/Caption |
| 表单标签 | Label/Form |
| 辅助说明 | Body/Support |
| 小号主按钮文字 | Button/Primary/S |
| 小号描边按钮文字 | Button/Outline/S |

字号、行高、字重和字距从实时样式读取，不在工作流里另维护一份数值表。样式更名或新增时按当前定义和语义选择，不能机械套用旧索引。

- 新文字实际引用对应 Text Style；只抄字体参数不算引用规范。
- 同文件解析实时样式 ID。跨文件先确认发布/导入能力；可导入时使用共享资产。本地 key 不证明已发布。
- 不能导入时，可在获准编辑的目标文件建立与实时定义一致的本地样式镜像，注明源与读取日期及不会自动同步；不擅自发布或重写规范源。
- Web 英文角色不推广到 App、H5 或中文；读取对应端/语言规则。缺口要说明，独立的布局工作可继续。
- 适用组件内部文字先保持组件定义；与本次基础规范冲突时说明冲突并处理本页，不能静默改源主组件。

### 组件与其他属性

- 优先从相关业务页或已确认的 Craftime 库复用组件实例。用组件属性、变体和允许的内容覆盖配置，保留主组件关联。
- 索引里的主组件是候选资产，并非全部已被批准为通用规范。重复名称先核对祖先平台分区、用途、状态和尺寸，不能按名称取第一个。
- 有对应 Variables 时绑定颜色、间距、圆角；文字和阴影用对应样式。没有变量时读取相关同端组件的属性、记录来源，不能从任意画面推断全站数值。
- Material / iOS 等已启用社区库不自动属于 Craftime。
- 新增但无现成组件的元素，可以在目标文件做明确标注的本地草案，复用已确认规则。基础缺口决定整页品牌或核心行为时，询问所需节点/规则，同时继续独立工作。
- 使用 Auto Layout 组织内容；页面宽度与必要状态以任务为准，保留布局和业务结构的设计自由。
- 仅编辑任务授权的目标。页面任务不自动授权改变或发布规范源、删除已有画板或调整文件权限。

## 交付检查

检查本次目标子树，不全文件重写历史页面：

1. 对新建/修改文字核对 Text Style 实际引用及字体、字重、字号、行高、字距；混合文字按段检查，引用存在但有覆盖也要核对。
2. 检查实例的实际主组件 ID/key、适用平台/状态，以及变量和样式的实际绑定。
3. 在任务范围内修复明确偏差；例外和未知分别记录。
4. 查看实际截图，确认字体效果、换行、溢出、对齐和需要的状态。结构检查不能代替截图检查。
5. 交付画板链接、规范来源、检查结果和未解决项。没有验证证据时，状态用“待验证”，不声称通过。

单独检查设计稿时使用 [规范检查](../craftime-review/SKILL.md)，默认只读。插件提供工作流程；合规以实际节点与截图证据为准。
