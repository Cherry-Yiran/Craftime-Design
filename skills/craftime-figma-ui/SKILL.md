## 开工

- 从任务确定平台（Web / App / H5）、语言、目标文件/画板和业务目标。能推断的直接执行；只澄清影响设计依据的歧义。
- 读取相关文字样式、变量、正式组件定义及用户指定的目标节点。未要求查找现有 UI 且不适用同模块移动端例外时，不读取业务页目录寻找参考，不浏览其他业务页；规范定义读取、指定目标检查和下文固定区域复用不构成自动查找业务 UI。只检查本次有关部分，不把封面读取结果当成完整文件。
- 先说明本页使用的规范来源与适用组件。区分明确基础规范、业务组件既有定义与本次方案选择。
- 通过本环境实际已连接的 Figma 工具操作。有 `use_figma` 时按其环境要求先加载 `figma-use`；整页与组件技能存在时按对应要求加载。没有这些专属工具/技能时，使用本环境官方工具指引，不能因名称不同就阻塞已有能力，也不假装具备原生写回能力。

用户的明确要求优先于插件约定；记录例外。旧走查、探索效果图和社区 UI Kit 不自动成为 Craftime 标准。

## 设计决策与交付范围 · 2026-11-02

设计前与交付检查时，按任务读取 [四项设计决策规则](references/design-decisions.md)。本聊天规范开关附加的工作流同样采用以下四项：

- **移动端独立设计**：先读取正式移动端布局/间距定义与同模块最新移动稿及截图，针对触屏和窄屏独立安排信息与控件；核对边距、行高、图文间距、尾部控件、热区和安全区，不直接缩小 Web。可查同模块 Mobile 参考，不扩大到其他业务或 Web；缺少来源标待验证。
- **简洁与信息密度**：用间距、对齐和分组建立层次，减少无用途分隔线、重复标题与辅助文案；卡片大小和单屏数量按内容判断。不缩小规范字号或热区来塞内容，不擅删用户提供信息，也不将局部截断行数或按钮尺寸升为全局规则。
- **图标语义避撞**：选型时对比当前页面及已提供的关联图标，避免“想做”“点赞”“收藏”等动作在含义与轮廓上混淆；在最终尺寸和控件上下文核对。MingCute 来源与可编辑描边要求仍保留；缺少对照标待验证，不借机搜索无关业务。
- **交付范围与定稿同步**：按目标媒介与规模交付，一屏样式使用代表数据，不导入整个 Demo 数据集；范围缩小时停止多余批量工作、清理本次临时内容并如实报告后台任务状态。同步前读取用户最新定稿；要求全部状态时逐项列出并读回实际目标，保留状态差异与已有交互，不能改一个示例就称全部完成。不自动恢复删除状态，删旧稿须有明确授权并检查引用。

四项纳入现有截图与交付检查，不新增审美评分、固定复审轮次或例行审批。结构化读回工具只检查提供的记录，不自动判断移动端适配、视觉密度、图标语义或全部状态完成情况。

- 用户直接指定的参考或目标可以读取；这不允许扩大到未指定的其他业务页面。用户要求先生图、只做素材或只排文案时，执行相应工作，不提前制作 Figma 页面。
- 在获准查找并选定对应设计后，直接复用原生节点：组件保留实例关联，普通 Frame / Group 复制原图层；只改本次所需内容，保留可编辑文字、布局、变量/样式绑定和交互。报告实际来源、复用范围与新增部分。
- 未要求查找且不适用同模块移动端例外时，可以按正式规范和任务需求设计内容区，不需要先完成业务页搜索。工具读取失败或跨文件复制受限不等于资产不存在，报告实际限制，不以失败为由静默重绘已指定资产。
- 跨文件先确认实际原生复制或导入能力，不能声称普通节点的同文件 clone 可直接跨文件使用。

开始选色和交付检查前，必须读取 [颜色用途与检查](references/color-semantics.md) 及其机器可读规则，先确定用途，再核对当前模式的变量、别名和实际渲染颜色。变量存在或 HEX 属于色阶，不证明选用正确。

- 2026-11-02 用户确认：普通内容分隔线改用 `#F2F2F2`、100% 不透明，默认视觉厚度 1px，覆盖此前分隔线 `中性/50` / `#E7E7E8` 的用途约定。`中性/50` 本身、骨架与禁用表面继续保留原值，不修改基础色阶。`border/subtle` 当前为 `#CECFD0`，用于装饰描边，不能套给普通分隔线；控件描边另用 `border/control`。具体组件已有明确特例或用户最新要求时，保留并记录来源，不扩展成全局规则。
- 构造代码中分别定义 `separator`、`decorativeBorder` 与 `controlBorder` 的颜色选择，不共用泛化的 `border` 颜色映射。不用降低 `#CECFD0` 的透明度模拟分隔色，不得虚构已发布变量。没有可用正式别名时，允许在获准目标内建立已确认规则的本地 `separator/default` / #F2F2F2，并注明来源、日期和未发布；不改共享变量来影响无关历史页面。

### 文字

2026-11-02用户要求避免功能文字过细。先读取[按用途选择字重](references/typography-roles.md)与[机器规则](references/typography-roles.json)：当前Web导航、分类、Tab、筛选、字段标签、主/次/文字按钮、行内操作和计数默认Open Sans600，未选中态也不降到400；页面标题700，分区/弹窗标题沿用600–700。400用于昵称、帖子/评论正文、内容小标签和明确的辅助元信息；可点击筛选不属于内容小标签。Regular400与Light300不能混为一谈。用户刚手动改后的字重优先，不自动改回旧值。

设计时先给每段文字确定semanticRole与usage.kind/purpose，再选样式。不能因Body/Compact或Caption恰好字号合适就拿其400字重做功能文字。旧样式仍为400/500时，在获准目标复用同字号/行高的600本地功能样式并标注来源，不改共享Regular变量或批量迁移历史稿。MakerWorld实测只参考字重分工，不照搬其尺寸、未选中Tab400或回复/数字500。英文Open Sans、中文实际设备字形分开核实；Mobile/App/H5仍读对应端来源。

已确认的文字角色来自 `Group/Craftime/Web/EN/`：

| 用途 | 样式后缀 |
| --- | --- |
| 页面标题 | Heading/Page |

| 注释 | Body/Caption |

| 辅助说明 | Body/Support |
| 小号主按钮文字 | Button/Primary/S |
| 小号描边按钮文字 | Button/Outline/S |

字号、行高和字距从实时样式读取；字重同时满足最新用途规则。旧实时样式的400/500不覆盖用户2026-11-02确认的功能文字600默认。样式更名或新增时按当前定义和语义选择，不能机械套用旧索引。

- 新文字实际引用对应 Text Style；只抄字体参数不算引用规范。
- 同文件解析实时样式 ID。跨文件先确认发布/导入能力；可导入时使用共享资产。本地 key 不证明已发布。
- 不能导入时，可在获准编辑的目标文件建立与实时定义一致的本地样式镜像，注明源与读取日期及不会自动同步；不擅自发布或重写规范源。
- Web 英文角色不推广到 App、H5 或中文；读取对应端/语言规则。缺口要说明，独立的布局工作可继续。
- 适用组件内部文字先保持组件定义；与本次基础规范冲突时说明冲突并处理本页，不能静默改源主组件。

### 组件与其他属性

- 优先从已确认的 Craftime 库或用户直接指定的资产复用组件实例。仅在用户要求查找现有 UI 或适用同模块移动端限定例外时，从获准查找的业务页选取组件。用组件属性、变体和允许的内容覆盖配置，保留主组件关联。
- 索引里的主组件是候选资产，并非全部已被批准为通用规范。重复名称先核对祖先平台分区、用途、状态和尺寸，不能按名称取第一个。
- 有对应 Variables 时绑定颜色、间距、圆角；文字和阴影用对应样式。没有变量时读取相关同端组件的属性、记录来源，不能从任意画面推断全站数值。
- Material / iOS 等已启用社区库不自动属于 Craftime。
- 新增但无现成组件的元素，可以在目标文件做明确标注的本地草案，复用已确认规则。基础缺口决定整页品牌或核心行为时，询问所需节点/规则，同时继续独立工作。
- 使用 Auto Layout 组织内容；页面宽度与必要状态以任务为准，保留布局和业务结构的设计自由。
- 仅编辑任务授权的目标。页面任务不自动授权改变或发布规范源、删除已有画板或调整文件权限。

## 机器检查与字体写回

执行 [读回检查](references/readback-checks.md)：将本次真实节点、实时定义、截图复核和固定区域基线交给 `craftime_check_design`；MCP 工具尚未被宿主加载时运行随包脚本。它仅检查提供的证据，不能自行读取 Figma，也不能将模拟记录当作设计验收。颜色继续执行原颜色语义检查。

遇到字体加载、字形缓存或原生导入问题时，先读 [字体异常与原生文字写回](references/font-writeback.md)。保留原生 TEXT，不改字体绕过失败；写回后核对真实字重、样式绑定与截图。

## 交付检查

检查本次目标子树，不全文件重写历史页面：

1. 对新建/修改文字核对Text Style实际引用与semanticRole、usage用途，按typography-roles.json验证实际fontWeight/wght。当前Web功能文字用400，即使actual与错误expected样式一致，也须判有偏差；未填写用途或只看字体菜单名则待验证。字号、行高、字距和混合段继续逐项读回，用户最新手改不得被旧样式覆盖。
2. 检查实例的实际主组件 ID/key、适用平台/状态，以及变量和样式的实际绑定；按 [颜色用途与检查](references/color-semantics.md) 检查颜色是否适合实际用途，特别核对分隔线与描边，记录检查输出。引用成功不等于语义正确。
3. 对本次新增/修改图标，按图标规则核对官网来源、原生可编辑路径、真实Stroke、最终尺寸下1.67px及变量绑定，并检查截图；filled path不等于可调描边，旧资产名称不证明合规。
4. 在任务范围内修复明确偏差；例外和未知分别记录。
5. 在现有截图检查中，同时判断字体效果、换行、溢出、对齐，以及配色协调、视觉主次、留白和控件轻重。设计时结合页面目的与背景选用表面和描边，不因色值合规就认定视觉成立。检查范围与改动相称：文案看换行与局部，控件看所在区域，整页重设计才看整体；复用本次已有截图和证据，不另设审美复审、评分报告或例行用户确认。发现可具体说明的问题才在授权范围修正并核对受影响部分；无明确问题即交付，不无故扩展或反复打磨。常规视觉取舍由助手判断；不覆盖明确规范、改共享源或受保护区域，也不把局部偏好升为全局规则。只读评审仍只给结论。结构检查不能代替截图检查；缺少截图时明确待验证，不冒充视觉通过。
6. 核对实际复用资产的来源（file key、节点 ID、平台和状态），报告新增部分；用户要求查找现有 UI 或适用同模块移动端例外时，报告实际查找范围与缺口。完整新页面核对默认导航和顶部是否来自上述精确节点并保持原样；已有页面核对保护区域的修改前后属性及截图，没有证据时标为待验证。
7. 按四项设计决策检查相关移动端来源与布局、信息密度、图标语义及交付目标清单；范围、定稿与完成证据对应，未核对的目标不能报完成。交付画板链接、规范来源、检查结果和未解决项。没有验证证据时，状态用“待验证”，不声称通过。

单独检查设计稿时使用 [规范检查](../craftime-review/SKILL.md)，默认只读。插件提供工作流程；合规以实际节点与截图证据为准。
